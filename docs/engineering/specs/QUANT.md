## 1. Mathematical Formulation

TARS quantizes continuous latent weights $W \in \mathbb{R}^{m \times n}$ into symmetric ternary states $\{-1, 0, +1\}$ scaled by a single scalar factor $W_0 \in \mathbb{R}^+$ per layer or output channel:

$$W_{\text{quant}} = W_0 \cdot Q(W)$$

where $Q(W) \in \{-1, 0, +1\}^{m \times n}$.

### 1.1 Scale Factor ($W_0$)

The scale factor $W_0$ is computed via mean absolute weight magnitude across the weight tensor:

$$W_0 = \frac{1}{m \cdot n} \sum_{i=1}^{m} \sum_{j=1}^{n} |W_{ij}|$$

When channel-wise scaling is configured, $W_0^{(j)}$ is evaluated independently across each output neuron row $j$.

### 1.2 Quantization Operator ($Q$)

The quantization operator maps latent floating-point weights into discrete trits using thresholding:

$$Q(W_{ij}) = \text{clip}\left(\text{round}\left(\frac{W_{ij}}{W_0}\right), -1, +1\right) = \begin{cases}
+1, & \text{if } W_{ij} > +0.5 \cdot W_0 \\
-1, & \text{if } W_{ij} < -0.5 \cdot W_0 \\
0, & \text{otherwise}
\end{cases}$$

### 1.3 Straight-Through Estimator (STE)

Because the gradient of a discrete step function is zero almost everywhere, backpropagation uses the Straight-Through Estimator (STE). The gradient of the loss $\mathcal{L}$ with respect to latent weights $W$ is evaluated using identity pass-through:

$$\frac{\partial \mathcal{L}}{\partial W} \approx \frac{\partial \mathcal{L}}{\partial W_{\text{quant}}}$$

Optionally, gradients are clipped outside $[-1.0, +1.0]$ to prevent unbounded latent weight divergence during optimization.

## 2. Canonical Hardware Code Serialization

When serializing quantized weights for the hardware NPU (`wt.mem`) or compact memory transfer, trits are mapped into 2-bit words following the canonical hardware identity $v = b_0 - b_1$ ($w = \{b_1, b_0\}$):

| Trit Value | Code ($b_1 b_0$) | Value ($v = b_0 - b_1$) | Encoder Policy | Hardware Decode (`t3_dec.sv`) |
| :---: | :---: | :---: | :--- | :--- |
| $0$ | `2'b00` | $0 - 0 = 0$ | **Canonical emission for zero** | `w_en = 0`, inactive |
| $+1$ | `2'b01` | $1 - 0 = +1$ | Canonical emission for $+1$ | `w_en = 1`, `w_s = 0` ($+a$) |
| $-1$ | `2'b10` | $0 - 1 = -1$ | Canonical emission for $-1$ | `w_en = 1`, `w_s = 1` ($-a$) |
| $0$ | `2'b11` | $1 - 1 = 0$ | **Never emitted** (redundant / fail-safe) | `w_en = 0`, inactive (cancels) |

### 2.1 Emitter Invariants
1. **Canonical Zero:** Encoders and serialization routines (`to_t3`, `export_model`) MUST emit `00` for zero. `11` is never generated by software.
2. **Decoder Acceptance:** All hardware and software decoders accept both `00` and `11` as valid representations of zero.
3. **Fail-Safe Integrity:** Erased or pull-up memory (`0xFF`, repeating `11`) decodes safely to all-zero activations.
4. **Hamming Distance:** $+1$ (`01`) and $-1$ (`10`) maintain Hamming distance 2; single-bit flips attenuate to zero rather than inverting signs.

## 3. Training and Quantization Execution Modes

| Mode | Forward Execution | Backward Execution | Export Target |
|---|---|---|---|
| **Float Reference (Baseline)** | $Y = X W^T + b$ in $f32$ | Analytical backpropagation | Model parameters in $f32$ |
| **Post-Training Quantization (PTQ)** | Evaluated on float model, followed by one-shot scale extraction and clipping | None | `wt.mem` (2-bit), `w0.mem` (Q8.24) |
| **Quantization-Aware Training (QAT)** | Forward pass uses quantized ternary weights $W_{\text{quant}} = W_0 \cdot Q(W)$ | Backward pass updates latent float weights via STE | Bit-exact golden vectors for NPU parity |

## 4. Interface Signatures

Per repository documentation policy, exact method interfaces are defined abstractly:

```rust
pub struct QuantizedWeights {
    pub codes: Vec<u8>, // Packed 2-bit codes (4 trits per byte)
    pub scale: f32,     // W0 scale parameter
}

pub trait Quantizer {
    fn compute_scale(&self, weights: &Tensor<f32>) -> f32;
    fn quantize(&self, weights: &Tensor<f32>) -> (Tensor<f32>, f32);
    fn encode_t3(&self, weights: &Tensor<f32>) -> QuantizedWeights;
}
```
