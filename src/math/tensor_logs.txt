The items marked BUG are compile-time or runtime defects. Items marked DESIGN or OPTIMIZATION require an intentional API/performance decision.
P0 — Fix compilation
- [ ] BUG | L23–27, L31–36: zeros() calls Self::from(), but that constructor is defined under T: Clone + Default; T: Zero + Clone does not establish Default. Move the core constructor and stride calculation into an appropriately unconstrained impl<T> or reconcile the bounds.
- [ ] BUG | L86, L149, L180, L193, L209, L227, L247, L267, L287, L306, L325: Replace Tensor::zeros(shape, self.dtype()) / Self::zeros(shape, self.dtype()) with the generic zeros(shape) API. zeros() accepts one argument, and dtype() is not implemented. Supply the required Zero bound where used.
- [ ] BUG | L148–173: Make map, map_mut, and sum generic if they belong on Tensor<T>: use closures such as FnMut(T) -> T, return T from sum, and initialize with T::zero(). Alternatively, move f32-specific operations into impl Tensor<f32>.
- [ ] BUG | L176–220: Give outer, matvec, and matmul their actual numeric bounds (Mul<Output = T>, addition/accumulation, zero, etc.). Their current impl<T: Clone + Default> cannot compile numeric expressions for arbitrary T. Initialize accumulators with T::zero() instead of 0.0.
- [ ] BUG | L224–341: Replace impl<T: Add + Mul> with correct bounds for each operation. get/set need Clone; zeros needs Zero; Sub and Div are missing; and operator outputs must be constrained to T (e.g. Add<Output = T>). Consider separate impl blocks for each operation group.
- [ ] BUG | L305–339: Scalar operations hard-code s: f32, while the receiver is Tensor<T>. Either use s: T, add Mul<f32, Output = T> / Div<f32, Output = T> bounds, or specialize the implementation for f32.
- [ ] DESIGN | L10, L20: Integrate the DType trait into relevant implementations (it is currently not used as a bound). Decide which capabilities are universal to supported types and which are operation-specific; Add and Mul alone do not support subtraction, division, or creating zeros.
P1 — Fix correctness and edge cases
- [ ] BUG | L65–80: Correct the reversed step_logical assertion. assert_eq!(shape.len(), 0, "Vector size can't be zero") rejects all nonempty shapes and allows a zero-length shape that then underflows at shape.len() - 1.
- [ ] BUG | L65–80: Validate v.len() == shape.len() before indexing and define behavior for rank-zero tensors (shape == []). Consider returning a wrap/end indicator instead of relying on caller iteration counts.
- [ ] BUG | L32–49: Enforce data.len() == product(shape) in every public constructor. new() currently bypasses the validation performed by from_vec(), allowing invalid tensors.
- [ ] DESIGN | L100–104: Fix the contiguity predicate to match the intended semantics. Empty tensors are currently always noncontiguous; a nonzero offset does not inherently mean a view is noncontiguous; and size-one axes can have irrelevant strides. If you require canonical packed storage rather than logical contiguity, name/document that stricter condition separately.
- [ ] DESIGN | L323–339, L285–303: Define consistent division-by-zero behavior: div_scalar() checks zero, div_scalar_mut() does not, and tensor/tensor division has no explicit policy. Integer and floating-point dtypes behave differently.
- [ ] ROBUSTNESS | L25, L47, L55–61, L350–359, L385–386: Consider checked arithmetic for shape products, stride multiplication, index multiplication, and offset addition. Verify the final physical index is inside storage if arbitrary views/offsets become constructible.
- [ ] DESIGN | L14, L118–145, L367–370: Document view mutation semantics. transpose() shares an Arc, but set() uses Arc::make_mut() (copy-on-write), so writing to a transposed tensor will not update its original when shared. This is valid value semantics but not aliasing view semantics.
P2 — Simplify the API and improve performance
- [ ] DESIGN | L31–63: Remove unnecessary Clone + Default bounds from new, from, from_vec, and contiguous_strides. A constructor consuming an owned Vec<T> generally does not need either bound; from_slice does require Clone.
- [ ] DESIGN | L343–386: Move shape, strides, offset, numel, and index-calculation/access methods that do not clone into a less-constrained impl<T>. Keep Clone only on operations that actually clone values or call Arc::make_mut().
- [ ] OPTIMIZATION | L362–365: Consider a borrowed getter (get_ref() -> &T or a checked Option<&T>) alongside a value-returning get(); unconditional cloning can be expensive for non-Copy elements.
- [ ] OPTIMIZATION | L65–80: Accept slices (&[usize], &mut [usize]) instead of &Vec<usize> / &mut Vec<usize>. Avoid exposing the low-level index incrementer unless necessary.
- [ ] OPTIMIZATION | L82–96, L148–173, L225–339: Consolidate the repeated logical-index traversal used by contiguous conversion, mapping, reductions, and elementwise operations. Use a strided iterator or offset iterator to reduce boilerplate and indexing overhead.
- [ ] OPTIMIZATION | L189–220: Evaluate matrix-multiplication iteration order, bounds-check overhead, and contiguous fast paths. The current multiplication is mathematically conventional, but the k → i → j loop order can be unfriendly to row-major memory access.
- [ ] OPTIMIZATION | L367–370: Be aware that the first write through a shared Arc<Vec<T>> clones the entire backing vector, potentially expensive for large tensors and small views. Confirm this is acceptable for the intended tensor/view model.
- [ ] CLEANUP | L1–4, L47, L226 and similar: Remove unused imports, replace empty assert_eq! messages with useful diagnostics, and standardize failure messages.
- [ ] CLEANUP | L6–8, L22–388: Separate storage/constructors, layout/indexing, view operations, elementwise arithmetic, and linear algebra into distinct modules or impl blocks after correcting trait bounds.
P3 — Add regression tests
- [ ] Construct a valid tensor and assert invalid shape/data lengths are rejected consistently by new and from_vec.
- [ ] Test zeros() for ordinary, empty ([0, n]), and scalar ([]) shapes.
- [ ] Test step_logical() on [2, 3], its final wraparound, mismatched index lengths, and zero-dimensional shapes.
- [ ] Test transpose indexing, transposed map, and make_contiguous, including shape/stride/value preservation.
- [ ] Test contiguity for normal tensors, transposed tensors, singleton dimensions, empty tensors, and offset views (once supported).
- [ ] Test elementwise add, sub, mul, and div in both immutable and _mut forms; include size mismatches and zero divisors.
- [ ] Test outer, matvec, matmul, and sum against hand-calculated results, including noncontiguous input views.
- [ ] Test clone/copy-on-write: mutate one tensor after cloning or transposing it and confirm the documented sharing behavior.
- [ ] Compile and exercise at least two supported element types (e.g. f32 and i32) to validate the generic API and operation-specific constraints.
Suggested repair order
1. Move core constructors, stride generation, and metadata accessors into appropriately bounded impl blocks.
2. Correct step_logical and shape/data invariants.
3. Remove the obsolete runtime dtype() calls and align the generic arithmetic bounds and signatures.
4. Define logical contiguity, copy-on-write, and division semantics.
5. Add correctness tests before performance refactoring.
